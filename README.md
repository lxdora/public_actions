## 掘金定时签到

每天自动签到，签到后触发一次免费抽奖，执行结果通过邮件 / pushplus / 钉钉通知。
基于 GitHub Actions 免费额度运行，无需自己的服务器。

## 使用方法

**1. Fork 本仓库**

**2. 打开该仓库的 Settings → Secrets and variables → Actions，新建下列 Secret**

| key | value | 是否必填 |
| --- | --- | --- |
| `COOKIE` | 掘金登录态 Cookie | **是** |
| `USER` | 发件邮箱地址，需开启 SMTP | 否，不填则跳过邮件通知 |
| `PASS` | 该邮箱的 SMTP 授权码（不是邮箱登录密码） | 否 |
| `TO` | 接收邮件的邮箱 | 否 |
| `PUSH_PLUS_TOKEN` | pushplus 的 token | 否 |
| `DING_TOKEN` | 钉钉机器人 Webhook 的 access_token | 否 |
| `DING_SIGN` | 钉钉机器人安全设置中的加签密钥 | 否 |

获取 Cookie：浏览器登录掘金 → F12 → Network → 任选一个 `api.juejin.cn` 请求 → 复制 Request Headers 里 `cookie` 的完整值。

> 掘金 Cookie 有效期约一个月，**过期后需要重新更新 `COOKIE` Secret**。
> 过期时任务会失败并变红，这是预期行为——用来提醒你换 Cookie。

**3. 启用 Actions**

Fork 出来的仓库默认可能没开 Actions。进入 Actions 页面确认已启用；若工作流显示为被禁用，
在左侧选中 `JueJin_Helper` 后点 Enable workflow。

**4. 手动验证**

在 Actions → JueJin_Helper → Run workflow 手动跑一次。日志会逐项打印结果：

```
== 掘金签到 2026年10月28日 ==
签到前矿石：1240
  [ok]   签到：签到成功
  [ok]   免费抽奖：抽奖成功，获得：xxx
签到后矿石：1280（本次变动 +40）
== 汇总：共 5 项，失败 0 项 ==
```

之后每天北京时间 **07:37** 左右自动执行（cron 用 UTC，配置的是 `37 23 * * *`；避开整点可减少排队延迟，实际触发时间会有几分钟浮动）。

> ⚠️ **GitHub 会自动禁用长期不活跃的仓库里的定时任务。** 如果仓库长时间没有任何新提交，
> 工作流会进入 `disabled_inactivity` 状态并静默停止运行——这是本仓库原作者断更后失效的原因。
> 建议偶尔改动一下（调整 cron、改个配置文件都行），使仓库保持活跃。

## 退出码

| 退出码 | 含义 |
| --- | --- |
| `0` | 全部成功 |
| `1` | **签到失败**（Cookie 过期等），Actions 显示红色 ✗ |
| `2` | 未配置 `COOKIE`，配置错误 |
| `3` | 签到成功，但有非关键项失败（抽奖异常 / 通知渠道发送失败） |

旧版本所有步骤都被 try/catch 吞掉，退出码永远是 0，跑挂了也显示绿色成功——这也是排查困难的主要原因，本版已修复。

## 相比原版改了什么

| 项目 | 原版 | 本版 |
| --- | --- | --- |
| Actions | `checkout@v2` + `setup-node@v1` + Node 12 | `checkout@v4` + `setup-node@v4` + Node 20，带 npm 缓存 |
| job 结构 | `build` / `send` 两个 job，`build` 毫无用处并重复安装依赖 | 合并为单个 job |
| 失败感知 | 全部 try/catch 吞掉，永远退出 0 | 关键步骤失败 `exit 1`，Actions 变红 |
| 邮件通知 | `sendMail` 被 require 但**从未调用**，是死代码 | 已接上，且修复了 `secureConnection` 这个非标准的 nodemailer 选项 |
| 挖矿游戏 | `juejin-game.bytedance.com` 已下线 | 移除 |
| 沾喜气 | `lottery_lucky/dip_lucky` 返回"请求路由不存在" | 移除 |
| 收集 Bug | `user_api/v1/bugfix/*` 返回"请求路由不存在" | 移除 |
| 钉钉推送 | 未 return promise，错误被静默吞掉 | 返回 promise，自带加签实现，去掉 `ding-bot-sdk` 依赖 |
| pushplus | 用 `http://` 明文 | 改用 `https://`，并校验返回码 |
| 网络请求 | 无超时，挂起会拖死 job | 统一 15s 超时 + job 级 10 分钟上限 |
| 依赖 | 5 个（含已不再需要的 `got` / `jsonwebtoken` / `node-fetch` / `ding-bot-sdk`） | 仅剩 `nodemailer` 1 个 |
